# UPDATING.md — Weekly incremental update

How to add the latest tournaments to every published format (Standard, Modern, Premodern, Limited) without
redoing the history. A scheduled Claude session runs this every Monday and pushes to `main`
directly (the owner's choice: no pull request). A human can run it the same way.

Read `CLAUDE.md` (writing style, rules) and `AGENTS.md` (editorial schema, tools) first.

## What is committed, what is rebuilt

- `data-src/{format}/results.json`: every mtgtop8 result scraped so far, one per line. The weekly
  refresh scrapes the current year again (and last year in January–February) and replaces it.
- `data-src/{format}/editorial/{season}.json`: the editorial layer, edited by hand or by an agent.
- `src/data/{format}/`: generated by `build.py`. Its decklists double as a cache, so a fresh
  checkout rebuilds without downloading lists it already shows.
- `.pipeline/` (git-ignored): Scryfall bulk file, printings index, candidates, list cache.

## 1. Refresh

```bash
npm ci
bash scripts/pipeline/weekly.sh refresh
```

Downloads Scryfall's bulk data, rebuilds the printings index, scrapes new mtgtop8 results, groups
them (`cluster.py`) and prints, per format, what `pending.py` finds:

- `NEW SEASON: …`: a season has to be opened (step 2).
- per recent season: how many top 8s the editorial covers, then every mtgtop8 title with a top 8
  that no deck claims. `QUALIFIES` = enough top 8s on its own; `WIN` = won a Professional/Major
  event (check the event against the rule below: an MTGO Challenge is not a Regional Championship).

If no format has new results and nothing is pending that qualifies, stop here: no commit.

## 2. Open a new season (when announced)

- Modern, Premodern: one season per calendar year. Add `["2027", "2027-01-01", "<latest set>"]` to
  `scripts/pipeline/seasons.{format}.json` and `{ id: '2027', start: '2027-01-01', set: …, bans: [] }`
  to `src/data/{format}/seasons.ts`.
- Standard: a season opens with the first expansion released on or after August 1 (Wilds of
  Eldraine, Bloomburrow, Edge of Eternities…). Add `["2026-hob", "2026-08-14", "The Hobbit"]` to
  `scripts/pipeline/seasons.json` and the matching entry to `src/data/standard/seasons.ts`. Bans
  dated after the new start move to the new season.
- Run `MTG_FORMAT=… python3 scripts/pipeline/cluster.py`, then write
  `data-src/{format}/editorial/{new season}.json` (step 3). Results after the new start leave the
  previous season: run `check_editorial.py` on it too and drop titles that no longer exist there.

## 3. Editorial pass on the recent seasons

For each unassigned title (`deckinfo.py SEASON "Title" --all` shows its results and lists):

1. A variant or a misspelling of a deck already in the season (same engine, same key cards): add
   the title to that deck's `titles`. Most weeks, this is all there is to do.
2. A new archetype that meets the inclusion rule: add a deck. If it existed in an earlier season,
   reuse its `slug` and adapt its texts (`grep -l '"slug": "x"' data-src/{format}/editorial/*`);
   otherwise write `summary` and `why` following `CLAUDE.md`.
3. Junk titles ("Other", "Rogue", "Unknown") or one-off brews that do not qualify: leave them.
   A mislabelled single result can be moved with `include` (see `AGENTS.md`).

Inclusion rule, after merging titles into real archetypes:

| Format | Rule |
| --- | --- |
| Standard | top 8 ≥ 3, or an event win, or a top 4 at a Pro Tour / Worlds / Regional Championship |
| Modern | top 8 ≥ 5, or won a Pro Tour / World / Regional Championship (or equivalent), or a top 4 at a Pro Tour / Worlds |
| Premodern | top 8 ≥ 4, or won a 64+ player or Professional/Major-level event |

Do not rewrite the texts of existing decks unless a new fact makes them wrong (a deck that "never
won an event" just won one). Never type statistics: the site computes them.

## 3b. Limited (17Lands)

`weekly.sh refresh` also runs `scripts/pipeline/limited/refresh.py`: sets whose 17Lands dump
changed are processed again, and a newly released set is added to
`scripts/pipeline/seasons.limited.json` once 17Lands publishes its Premier Draft dump (about three
weeks after release). For a `NEW SET`, write `data-src/limited/editorial/{set}.json`: one entry per
color combination of `data-src/limited/stats/{set}.json` that has a 7-win deck (`rep`), following
the editorial rules of `AGENTS.md` (section Limited). `build_limited.py --check {set}` must report
0 errors.

## 4. Bans

Check for Banned & Restricted announcements since the last ban in `src/data/{format}/seasons.ts`:
magic.gg (Standard, Modern) and premodernmagic.com/blog (Premodern). Add each one with its source
URL in a comment, in the season whose dates contain it.

## 5. Build, check, publish

```bash
bash scripts/pipeline/weekly.sh build
```

Runs `check_editorial.py` on the two most recent seasons of each format, `fetch_result_lists.py`
on them (lists of the new results), `build.py`, `prices.py` (current card prices), content validation,
type-check and the production build. It must exit 0. Then:

```bash
git add -A data-src src scripts
git commit -m "Weekly update YYYY-MM-DD: <new results per format, decks added>"
git push origin HEAD:main
```

GitHub Actions deploys `main` to GitHub Pages. If the build cannot be fixed, do not push to `main`:
push to a branch named `weekly-update-YYYY-MM-DD` and report what failed.

Prices alone can be refreshed more often than the results (Scryfall updates them once a day):
`bash scripts/pipeline/weekly.sh prices` downloads the bulk data and rewrites every
`src/data/{format}/prices.json`; commit them with `Prices YYYY-MM-DD`.

## Rules

- mtgtop8 public results and decklists only. Never invent a result, a date or a number.
- Never delete decks of past seasons; only the recent seasons change week to week.
- A duplicate or non-competitive event goes to `data-src/{format}/date-fixes.json` with a reason.
